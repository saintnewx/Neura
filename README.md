# Neura

AI-генератор маркетингового контента: адаптивный лендинг, рабочая область `/app`, авторизация `/auth` и страница 404. Интерфейс на русском языке; правила оформления описаны в `DESIGN.md`.

## Стек технологий

- React 18 + Vite 6 + TypeScript со строгой проверкой типов.
- Tailwind CSS 3, React Router 6, Lucide React.
- Inter Variable из Google Fonts: body 510, подзаголовки 590.
- CSS-анимации, Intersection Observer и typewriter без библиотек анимации.
- Vercel Node.js Function и NVIDIA Chat Completions API.
- Supabase JS, Supabase Auth UI, PostgreSQL с RLS.

## Запуск

Нужен Node.js 22.12+ или 24 LTS.

```bash
npm install
npm run dev
```

Vite запустит приложение по адресу `http://localhost:5173`.

`npm run dev` запускает только клиент. Для локальной генерации через серверную функцию установите Vercel CLI, создайте `.env.local` по образцу `.env.example`, укажите `NVIDIA_API_KEY` и запустите `vercel dev`. Vercel CLI использует Vite для клиента и обслуживает `/api/generate`.

```bash
npm run build
npm run preview
```

Сборка сначала проверяет TypeScript, затем создаёт production-файлы в `dist/`. В репозитории включён `package-lock.json`; для воспроизводимой установки можно использовать `npm ci`.

## Генерация контента

`src/lib/api.ts` отправляет POST `/api/generate` с JSON `{ "task": "...", "type": "Пост", "tone": "Дружелюбный" }`. Вошедшие пользователи также передают `Authorization: Bearer <access_token>`: сервер проверяет JWT через Supabase и атомарно резервирует дневной лимит. Затем серверная функция запрашивает NVIDIA с `stream: true` и открывает SSE-поток: заголовки и стартовый комментарий отправляются до ожидания первого токена. Каждый полученный фрагмент `delta.content` сразу передаётся отдельным событием `data: {"content":"..."}`. Успешный ответ не читается целиком через `json()` или `text()`. Внутренняя reasoning-метаинформация модели в браузер не передаётся.

Клиент читает `response.body` через `ReadableStream.getReader()`, собирает SSE-события с учётом произвольных границ сетевых чанков и UTF-8 и обновляет видимый результат при каждом фрагменте. Skeleton исчезает после первого текста, а кнопки копирования и перегенерации появляются после `data: [DONE]`. До завершения потока ввод заблокирован. При уходе со страницы запрос отменяется; сервер отменяет запрос NVIDIA при закрытии соединения клиентом.

Ошибки валидации и отсутствие ключа возвращаются обычным JSON `{ "error": "..." }` с HTTP-кодом. После открытия потока HTTP-статус уже 200: ошибки NVIDIA и тайм-ауты передаются SSE-событием `data: {"error":"...","status":502}`. Клиент обрабатывает оба варианта и показывает сообщение рядом с кнопкой «Попробовать снова». Если поток оборвался, уже полученный текст остаётся видимым. Отсутствие `[DONE]` не считается успешной генерацией.

«Перегенерировать» повторяет последнюю отправленную задачу с тем же форматом и тоном. Сервер принимает только POST, непустые задачи длиной до 2000 символов и форматы Пост/Email/Реклама/Reels. Без настроенного ключа возвращается понятная ошибка 503. Обрабатываются ограничения NVIDIA, ошибки авторизации, недоступность модели, сетевые ошибки и пустые/некорректные ответы. Сервер отводит 55 секунд на проверку квоты и NVIDIA, клиент — 65 секунд, функция Vercel — 60 секунд. Каждый запрос к Supabase на сервере ограничен 8 секундами. Сервер отправляет SSE heartbeat каждые 10 секунд для поддержания соединения в периоды ожидания; это не продлевает общий лимит функции.

«Копировать» использует Clipboard API, которому нужен HTTPS или localhost. При успехе toast виден две секунды; при запрете доступа предлагается ручное копирование. Мобильное меню поддерживает Escape, удержание фокуса и закрытие по ссылке. Анимации учитывают `prefers-reduced-motion`.

Реальный AI подключён через NVIDIA. Задачи передаются провайдеру; готовые тексты сохраняются в истории. Аккаунты и дневные лимиты подключены через Supabase. Платежи пока не подключены: выбор Pro или Team не меняет план и размер квоты. Цены, компании и отзывы — демонстрационный контент. Перед коммерческим запуском замените примеры подтверждёнными данными и подключите оплату и социальные профили.

## Подключение Supabase

Проект Supabase: **supabase-copper-marble**. Интеграция Vercel уже может предоставить публичные переменные; код использует именно `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY`.

1. Откройте проект **supabase-copper-marble → SQL Editor**, вставьте весь `supabase/schema.sql` и выполните его. Интеграция Vercel создаёт переменные окружения, но не применяет схему автоматически. Файл можно выполнить повторно; он управляет политиками двух таблиц Neura.
2. В **Authentication → URL Configuration** укажите production-домен Neura как **Site URL** и добавьте `https://ВАШ-ДОМЕН/app` в **Redirect URLs**. Для локальной работы также добавьте `http://localhost:3000/app` или фактический адрес `vercel dev`.
3. Включите Email и **Google** в **Authentication → Providers**, задайте Google OAuth client ID/secret и добавьте callback URL, показанный Supabase, в разрешённые адреса Google OAuth.
4. Проверьте, что в Vercel переменные `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY` доступны для нужных окружений. Сделайте **Redeploy**: Vite встраивает публичные значения при сборке. Эти же переменные читает Vercel-функция через `process.env` для проверки квоты.
5. Откройте `/auth`, зарегистрируйтесь или войдите через Google. При включённом подтверждении email сначала откройте ссылку из письма. После входа приложение переводит на `/app`.

Используйте публичный anon key. Service-role key не нужен: доступ определяется JWT пользователя и RLS. При отсутствии переменных `src/lib/supabase.ts` экспортирует `null`, пишет диагностическое сообщение в консоль, а генератор продолжает работать в гостевом режиме.

`AuthProvider` ждёт завершения инициализации SDK, затем читает `getSession()` и подписывается на `onAuthStateChange`. Клиент создан с `detectSessionInUrl: true`: Supabase обрабатывает Google-редирект и сохраняет сессию. Если восстановить вход не удалось, `/app` показывает причину. После входа хедер, история и лимит переключаются на аккаунт, после выхода — на гостевой режим. В консоли Safari сообщения `[Neura auth] getSession`, `onAuthStateChange` и `user` показывают состояние, ID/email и ошибки; токены в лог не выводятся.

### История и приватность

- Без входа история хранится в `localStorage` (`neura.generations.v1`) этого браузера. Сохраняются задача, формат, тон и готовый текст; последние 100 записей можно открыть повторно.
- После входа `/app` загружает последние 100 записей из `generations` текущего пользователя и сохраняет новые в Supabase. Гостевая история остаётся отдельной и автоматически не загружается в аккаунт.
- Триггер `auth.users` создаёт профиль при email- или Google-регистрации и обновляет email. Схема также создаёт профили для уже существующих пользователей.
- RLS разрешает пользователю SELECT/INSERT только своей истории и чтение своего профиля. Прямое изменение плана и счётчиков из браузера запрещено.
- При ошибке облачного сохранения результат остаётся на экране и попадает в отдельную очередь восстановления текущего аккаунта. «Повторить сохранение» использует тот же UUID, чтобы не создавать дубли.
- При выходе или смене аккаунта незавершённая генерация отменяется; чужая история не остаётся в интерфейсе.

### Дневные лимиты

- Гость: **5 запусков в день**, счётчик `neura.usage.v1` в localStorage. При поддержке Web Locks резервирование согласуется между вкладками. Это ограничение браузера: очистка localStorage сбрасывает гостевой счётчик.
- Аккаунт: **20 запусков в день**, `profiles.generations_today` и `last_reset_date`. Сервер сначала проверяет JWT, затем вызывает `reserve_generation()`; PostgreSQL блокирует строку профиля и атомарно проверяет лимит. Клиент не может увеличить квоту изменением запроса.
- Сброс происходит в **00:00 UTC** при следующем чтении или резервировании; cron не нужен. `get_daily_usage()` возвращает текущий счётчик для интерфейса.
- Один принятый запуск расходует слот, включая перегенерацию, отменённый запрос или ошибку NVIDIA. История сохраняется только после успешного завершения потока; повторное сохранение истории слот не расходует.
- При превышении открывается модалка «Лимит исчерпан. Оформите Pro или вернитесь завтра». Платные подписки пока не подключены; ссылка ведёт к тарифам.
- Если Supabase или схема недоступны, запрос вошедшего пользователя останавливается с понятной ошибкой, не переходя незаметно в гостевой режим.

## Деплой на Vercel

1. Запушьте проект в GitHub-репозиторий `neura`.
2. В Vercel выберите **Add New → Project** и импортируйте `neura`.
3. Выберите preset **Vite**. Если проект находится в подпапке, укажите её как **Root Directory**.
4. Установите **Build Command**: `npm run build`, **Output Directory**: `dist`, **Install Command**: `npm ci`.
5. В **Settings → Environment Variables** добавьте `NVIDIA_API_KEY` для **Production** и при необходимости **Preview**. Значение — ваш NVIDIA API key; не используйте префикс `VITE_`.
6. Выберите Node.js 24.x и нажмите **Deploy**. Если переменная добавлена после деплоя, сделайте **Redeploy**: существующий деплой не получит её автоматически.
7. Примените схему и настройки Supabase из раздела выше. Проверьте генерацию, `/auth`, прямой переход и обновление `/app`, вход/выход и неизвестный маршрут.

Функция экспортирует `maxDuration = 60`; для отдельной Node.js Function фактический лимит явно задан в `vercel.json`: `functions["api/generate.ts"].maxDuration = 60`. Конфигурация применяется при новом деплое. Streaming позволяет получать текст до окончания генерации, но не отменяет лимит общей длительности Vercel: в него входят ожидание NVIDIA и весь поток.

Для диагностики откройте `/api/ping`: он отвечает `{ "ok": true, "time": 1234567890000 }` с текущим Unix-временем в миллисекундах. Эндпоинт не использует NVIDIA или переменные окружения и не кэшируется. Проверить начало потока можно командой `curl -N -H 'Content-Type: application/json' -d '{"task":"Напиши короткий пост для кофейни","type":"Пост"}' https://ВАШ-ДОМЕН/api/generate`. Стартовый комментарий должен прийти сразу, фрагменты текста — до `[DONE]`.

`vercel.json` исключает `/api` и `/api/*` из SPA rewrite и перенаправляет клиентские маршруты на `index.html`; существующие статические assets Vercel отдаёт как файлы. `/api/generate` обслуживает Node.js Function, а React Router обрабатывает `/app` и страницу 404 после обновления браузера. Сервер вернёт SPA с HTTP 200 для неизвестного клиентского пути; визуальный 404 показывает React.

OG-карточка предоставлена в SVG согласно ТЗ. Некоторые социальные платформы требуют PNG/JPEG: при production-запуске экспортируйте SVG в PNG 1200×630, обновите `og:image` на абсолютный публичный URL и проверьте preview в нужной платформе.

## NVIDIA API

Серверная интеграция находится в `api/generate.ts`, клиент — в `src/lib/api.ts`.

- Endpoint: `https://integrate.api.nvidia.com/v1/chat/completions`.
- Модель: `openai/gpt-oss-20b`.
- Параметры: `temperature: 0.8`, `max_tokens: 800`, `stream: true`.
- System-промпт: «Ты — профессиональный копирайтер. Пиши живо, конкретно, без воды. Учитывай тип контента: Пост/Email/Реклама/Reels.»
- Формат и описание задачи передаются в отдельном user-сообщении.
- Для NVIDIA требуется серверная переменная `NVIDIA_API_KEY`; для аккаунтов — две публичные переменные Supabase из `.env.example`.

Сервер читает SSE NVIDIA, извлекает `choices[0].delta.content` и сразу пересылает его в браузер. Перед каждым следующим чтением учитывается backpressure соединения с клиентом. HTTP- и потоковые ошибки имеют поле `error` с исходным статусом и текстом NVIDIA (например, `401 Unauthorized: Invalid API Key`). Полный ответ ошибки и ошибки потока записываются в Vercel Logs через `console.log`. На экране показывается этот текст вместо общего заголовка. Если провайдер отразил ключ в ответе, его значение заменяется на `[REDACTED]` перед логированием и отправкой клиенту. Поток не кэшируется и имеет `Cache-Control: no-cache, no-store, no-transform`, а также `X-Accel-Buffering: no`.

**Никогда не вызывайте NVIDIA API с секретным ключом из браузера и не коммитьте `.env`.**
